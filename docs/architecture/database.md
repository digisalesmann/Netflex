# NetFlex — Database Reference

PostgreSQL 17, Prisma 6.19. Schema: `packages/database/prisma/schema.prisma`. Migrations: `packages/database/prisma/migrations/`.

## Migration history

| Migration                                     | Purpose                                                                                       |
| --------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `20261028232128_init`                         | All tables, enums, foreign keys, basic unique indexes (generated by Prisma)                   |
| `20261028232200_integrity_constraints`        | CHECK constraints, partial unique indexes, immutability/append-only triggers                  |
| `20261028233500_settings_partial_unique`      | Replaces a NULLS NOT DISTINCT index with two partial indexes so Prisma sees no drift          |
| `20261028234500_fix_group_members_null_check` | Fixes a NULL-passing CHECK on room/floor plan member caps (found by an integration test)      |
| `…_auth_fields`                               | MFA replay step, forced password change, owner-only platform grants (trigger), contact checks |
| `…_order_access_token`                        | Guest order token verifier, canonical device MACs                                             |
| `…_voucher_delivery`                          | Encrypted paid-voucher delivery, payment checkout URL                                         |
| `…_record_duplicate_charges`                  | Allows recording a real duplicate charge; single fulfilment stays guaranteed by subscriptions |

Rules:

- Never edit an applied migration; add a new one.
- Production uses `prisma migrate deploy` only. `migrate reset` is never run outside a disposable local database.
- CI checks for drift: `prisma migrate diff --from-schema-datasource … --to-schema-datamodel … --exit-code`.
- Hand-written CHECKs must be NULL-safe: a CHECK passes when its expression is NULL, so write `col IS NOT NULL AND col BETWEEN …`.

## Invariants the database enforces

| Invariant                                                                | Mechanism                                                                                                       |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Rooms/floors can't point at another property's floor/building            | Composite FKs `(floorId, propertyId)` → `floors(id, propertyId)`                                                |
| Money is positive integer minor units with ISO currency                  | CHECKs on plan_versions, orders, payments, refunds                                                              |
| Refunded amount ≤ paid amount                                            | `payments_refunded_range`                                                                                       |
| Refund requester ≠ approver                                              | `refunds_four_eyes`                                                                                             |
| Exactly one target per scope (INDIVIDUAL/ROOM/FLOOR)                     | `*_scope_target` CHECKs on orders, subscriptions, entitlements; `group_authorities_target`                      |
| Order fulfilled at most once (a duplicate real charge is still recorded) | Unique `subscriptions.orderId` (index `payments_one_success_per_order` removed in `…_record_duplicate_charges`) |
| Provider reference unique per provider                                   | `@@unique([provider, providerReference])`                                                                       |
| Webhook deduplication                                                    | `@@unique([provider, fingerprint])` on payment_events                                                           |
| One subscription per order, one entitlement per subscription             | Unique FKs                                                                                                      |
| Entitlement window coherent; ACTIVE/SUSPENDED need expiry                | `entitlements_window`, `entitlements_active_has_window`                                                         |
| Paid vouchers need an order; others need issuer + reason                 | `vouchers_issuance_record`                                                                                      |
| Voucher verifier is 64-hex HMAC (never plaintext), unique                | `vouchers_verifier_hex` + unique index                                                                          |
| One live voucher per entitlement                                         | Partial unique `vouchers_one_live_per_entitlement`                                                              |
| One active device slot per voucher/device                                | Partial unique `voucher_redemptions_one_active`                                                                 |
| One open room assignment per tenant per property                         | Partial unique `tenant_assignments_one_open`                                                                    |
| Plan version immutable once used; lock can't be removed                  | Trigger `plan_versions_guard`                                                                                   |
| Order/payment amounts, terms, references immutable                       | Triggers `orders_guard`, `payments_guard`, `subscriptions_guard`                                                |
| Financial history never deleted                                          | Delete-blocking triggers on orders, payments, payment_events, refunds                                           |
| Audit log append-only (no UPDATE/DELETE/TRUNCATE)                        | Triggers on audit_logs                                                                                          |

Production note: the application's database role must **not** own the tables, so it can't disable triggers. Migrations run as a separate owner role. This goes into the deployment runbook.

## Main query paths and indexes

| Query                                              | Index                                       |
| -------------------------------------------------- | ------------------------------------------- |
| Outbox relay: undispatched events by `availableAt` | `outbox_events_pending` (partial)           |
| Expiry job: entitlements due                       | `entitlements_expiry_due` (partial)         |
| Pending-payment reconciliation                     | `payments(status, createdAt)`               |
| Admin order lists per property                     | `orders(propertyId, status, createdAt)`     |
| Voucher support lookup by hint                     | `vouchers(hint)`                            |
| Network-operation retry scan                       | `network_operations(status, nextAttemptAt)` |
| Audit by property/target/actor                     | three `audit_logs` indexes                  |

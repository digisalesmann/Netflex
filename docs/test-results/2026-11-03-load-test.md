# Load test, 3 November 2026

Script: `node scripts/load/load-test.mjs <baseUrl> <users at once> <seconds> <lodge>`. It's read-only: it loads the home page, the plans page, the lodge details, the plan list and the health check in a loop. Nothing is bought, created or emailed.

## Live site (netflexhq.com, Railway), 20 users at once for 30 seconds

| Route               | Requests | Median | 95% under | 99% under | Errors |
| ------------------- | -------- | ------ | --------- | --------- | ------ |
| Home page           | 214      | 579 ms | 749 ms    | 2,136 ms  | 0      |
| Plans page          | 212      | 550 ms | 704 ms    | 2,127 ms  | 0      |
| Lodge details (API) | 209      | 508 ms | 568 ms    | 1,541 ms  | 0      |
| Plan list (API)     | 209      | 513 ms | 793 ms    | 1,409 ms  | 0      |
| Health              | 211      | 509 ms | 630 ms    | 1,903 ms  | 0      |

1,055 requests, 34.6 per second, **no errors**. About 500 ms of every request is the round trip between the test machine and Railway's servers: even the health check, which does almost nothing, takes about 500 ms. The servers themselves add little.

## Local production build, 50 users at once for 30 seconds

3,480 requests, 115.5 per second, **no errors**. API calls: median 100–170 ms. Full pages: median 0.6–1 s, rendered on one laptop.

## What this means for ND Lodge

The lodge has 31 rooms. Even if every resident opened the site at the same moment, that is about a third of the live test's 20 users clicking nonstop, and the site served them all without errors. The real limit for residents is the Wi-Fi itself: the Starlink connection and three Wi-Fi 4 access points. These are tested on site in the proof of concept (gate G6), not here.

Run the test again after big changes, and point it at the live site only at quiet times:

```sh
node scripts/load/load-test.mjs https://netflexhq.com 20 30 nd-lodge
```
